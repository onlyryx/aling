# ALING 下一阶段更新方案

日期：2026-10-10。状态：本方案对应的 v0.2.0、v0.2.1 和 v0.3 功能已完成实现；
发布前验证见 [verification.md](verification.md)。
以下保留最初的分阶段规划；最终合并为 v0.3.0 候选版本，当前命令与默认值以 README 为准。
维护者：Jack233_ / onlyryx。基线：`main` 的 `5d2f656`，项目版本 `0.1.0`。

## 1. 目标与取舍

延续“实用工具为核心，AI 群友为辅助”的定位。下一次大更新的验收目标是：
别人从 GitHub 获取源码后，能顺利配置、连接、排障；群成员能明确调用网页和
表情包功能；贡献者可以根据一个完整示例扩展插件。

沿用 Python、NoneBot2、OneBot V11、NapCat、SQLite 和现有服务分层。
本轮不引入新的机器人框架、插件商店、Redis、向量数据库或 Web 管理后台。

| 方向 | 收益 | 代价 | 建议 |
| --- | --- | --- | --- |
| 工具与部署体验优先 | 新用户能完成任务，也能排查接入问题 | 聊天人格变化较少 | 作为 v0.2.0 主线 |
| 会话与人格优先 | 多轮聊天更自然 | 增加上下文隐私、成本和模型兼容问题 | 放在 v0.2.1 |
| 工具、记忆、群管理、主动互动同时交付 | 一次增加多种能力 | 测试和权限边界交织，难以独立验收 | 分版本交付 |

## 2. 已有基础

- `/help`、`/ping`、`/proactive on|off`，群内明确 @ 的单轮 AI 聊天。
- 独立权限验证、群允许列表、AI 限频与并发、隐私日志、SQLite 群开关。
- `SafeWebClient` 已有 URL/DNS 检查、IP 固定、超时、大小与文本 MIME 限制，
  但没有群网页命令；重定向和压缩响应当前被拒绝。
- `MemeProvider`、`WebParser`、`GroupAction` 是协议，尚无表情包提供者或群管理实现。
- NoneBot 原生插件加载和 `PluginMetadata` 已在使用；目前 `/help` 仍是固定文本。
- `/health` 只代表进程可用，不代表 QQ 在线；没有会话历史、AI 工具执行或主动调度。
- 59 项本地测试和首次远端 CI 已通过；真实 QQ 接入、群指令和 AI 回复已由维护者验证。

这份方案没有读取真实 `.env`、账号资料或群聊数据库。

## 3. v0.2.0：实用工具与开源交付

### 3.1 接入诊断与状态（P0）

增加拟定命令 `uv run aling doctor`：默认进行离线配置、依赖、数据目录可写性、
本地端口冲突检查，输出配置项是否有效，不输出值。外部模型探测另用显式选项，
离线检查不启动 NapCat、不登录 QQ、不调用付费模型。

增加运行中的连接状态：OneBot 是否连接、适配器报告的 `online` / `good`、
最后一次收到事件的时间。无新事件只表示暂时没有上报，不直接判定离线或风控。
`online` 无法查询时显示“未知”，不伪造状态；异常归类为配置、连接、模型或发送失败。
最终实现中的 `/status` 仅供配置的超级用户查看有限状态，不包含密钥、账号列表、
消息正文、完整 URL 或异常请求体。

`/health` 保持现有进程存活语义。连接就绪状态另设 `/ready`，不用于阻塞
Compose 中 NapCat 的启动依赖，否则会造成 bot 等 QQ、NapCat 等 bot 的启动死锁。

验收：未登录、连接断开、在线状态未知、权限不足与端口占用都给出准确提示。
手机端账号功能限制不能靠 OneBot 状态可靠识别；提供人工排查流程，避免自动
重复登录、重启或重发消息。发送限频降低频繁操作，不能保证账号不触发风控。

### 3.2 群功能配置与帮助（P0）

拟定 `/feature ai|web|meme on|off`，群主、群管理员和配置的超级用户可操作。
部署者的全局开关是上限，群内命令不能启用全局禁用的能力，不能修改模型地址、
密钥、群允许列表或安装插件。新 web/meme 功能的全局开关初始关闭，启用方法
写入安装指南；最终采用群功能默认关闭、显式启用的策略。主动发言继续使用原有双开关。

基于已加载插件的原生元数据生成 `/help`，按实际配置和当前群开关展示可用能力；
保留原有命令与语法，未知命令提供简短指引。人格中的能力说明也从真实状态生成，
不再固定声称没有任何联网能力，也不声称已安装的功能全都对本群可用。

SQLite 新增版本化迁移和独立群功能配置表，保留 `group_settings` 与原开关。
迁移使用事务、明确列名和重复启动测试；当前存储有 `INSERT ... VALUES (?, ?)`，
不能直接添加列后继续沿用该写法。旧数据库、默认路径和 Compose 卷名保持兼容。
降级前需要维护者保留旧库备份，文档说明可恢复范围，禁止启动时自动删库重建。

验收：普通群员无法改配置；禁用功能不再调用外部服务；重启后开关仍在；旧库
迁移保留原设置；默认允许列表语义不悄悄改变，安装指南推荐显式设置目标群。

### 3.3 网页工具（P1，核心新功能）

拟定 `/read <URL>`，默认返回标题、来源和有限长度的正文摘录；
`/read <URL> --summary` 在 AI 可用时生成摘要。明确告诉使用者，摘要模式会把
选取的网页文字发给配置的模型服务；AI 关闭或失败时保留可用的正文摘录。

入口复用 `runtime.web.parse()`；输出遵守消息长度、调用冷却、并发和整体超时。
正文提取优先使用 `article` / `main`，剔除脚本、样式和常见导航。网页原文只在
本次任务内存中使用，不保存抓取历史。来源 URL 可展示在回复中，但不进入日志。

网页内容作为不可信资料传给摘要模型，不能覆盖人格、改配置、触发其他工具或
获取密钥。仍拒绝内网、混合 DNS、重定向、非标准端口和不支持的响应；第一版
不执行 JavaScript、不抓登录页面，不额外处理 PDF、视频或绕过网站访问限制。

验收：无 AI 时能阅读普通静态网页；摘要注明来源；超时、超限、重定向、空正文
和 SSRF 均有明确反馈；恶意网页中的指令不会造成工具执行。

### 3.4 表情包插件（P1，核心新功能）

拟定 `/meme <关键词>`，第一版按本地表情包目录的描述与标签检索，每次最多
发送一张图片。关键词为空、未匹配或图片发送失败都有自然的反馈。
这是一项本地库检索功能，帮助文案不称其为互联网表情包搜索。

实现现有 `MemeProvider` 的本地提供者，使用明确的资源编号和元数据索引。
群成员或 AI 不能提供任意本地文件路径；路径必须约束在指定目录内，包括符号
链接解析。图片校验真实格式、字节数与尺寸；外部图片下载是独立受限能力，
不能绕过现有网页客户端的文本 MIME 限制。

通过受控消息段发送验证后的图片数据，避免 NapCat 与 bot 两个容器的路径不一致。
表情包目录单独挂载，不占用代码目录；缓存只缓存资源，不缓存聊天。
仓库只包含自制或明确许可的演示素材及来源说明，维护者自己的素材不默认提交。
具体素材内容在实现时单独核对，不让第三方版权不明确的素材成为发布依赖。

验收：正常匹配、零结果、损坏图片、超大图片、目录逃逸、容器发送均覆盖；
未配置素材时解释如何启用；关闭功能后没有图片发送。

### 3.5 开源维护与发布（P1）

- 新手安装、NapCat Token 区分、Docker 网络地址、端口冲突和风控排障指南。
- `CONTRIBUTING.md`、问题/功能请求模板、PR 模板、变更记录和插件开发示例。
- 后续制定 `SECURITY.md`：支持版本、报告渠道、安全边界；先确认维护者可用的
  私密报告渠道，不编造邮箱或响应时限。
- 插件示例包括元数据、配置、群开关、权限、限频、隐私与离线测试，不另建插件框架。
- 清理 CI 已提示的 Action 运行时迁移事项，使用核对过的上游版本；依赖更新

## 4. v0.2.1：受控 AI 工具与短期会话

这两项各自独立启用、独立测试，不阻塞 v0.2.0 的工具命令交付。

**只读工具调用。** 在模型支持结构化 tool calls 且维护者显式启用时，
群内 `@阿零 帮我读一下这个链接……` 可以调用 `web.read`，
`@阿零 找个表示无语的表情` 可以调用 `meme.search`。
模型服务的普通 Chat Completions 兼容性不等于 tool calls 兼容性，必须分别验证。
不支持的服务继续使用单轮聊天和显式工具命令。

命令与 AI 工具复用同一个业务服务；AI 只选择白名单名称与经过校验的参数。
工具分发器执行群范围、群开关、限频和超时检查，返回成功或结构化失败。
默认每轮最多 2 次工具调用、每个工具最多 10 秒、整轮最多 45 秒；上限可配置，
拒绝循环工具调用。只将实际得到的结果交给模型，不把失败解释成成功。
图片由业务服务根据已验证资源编号发送，模型文字不能构造任意 CQ 段。
网页内容不能提升权限；不存在系统命令、代码执行、任意导入或群管理工具。

**短期会话。** 部署者与本群均显式启用后，只记住该用户明确 @ 的文字及
对应阿零回复，按 `(group_id, user_id)` 隔离。建议初始上限为 10 分钟、6 轮，
并设置每会话字符/模型输入预算和全局会话数量上限；过期清除、重启清空。
不接收普通群聊、回复引用的历史正文或其他用户的内容，不写 SQLite、日志或向量库。
提供 `/forget` 清除自己的会话，管理员禁用该群会话时立即清除该群缓存。
开启前明确告知短期上下文会发送到模型服务，原有关闭状态保持单轮行为。

验收：模型不支持工具、工具超时、参数注入、网页提示注入和循环调用可控；
上下文无跨用户/跨群混用，TTL、清除、关闭与全局内存上限有效。

## 5. v0.3：群管理与主动互动

**群管理先做明确指令。** 首批只考虑 `/mute`、`/unmute`，由真实群事件核验
调用者权限，再检查机器人自身权限和目标成员角色，不能把超级用户权限等同于
QQ 管理员权限。时长与目标经过验证，拒绝越权操作；AI 不提供管理入口。
踢人、批量管理、自动审核和全员禁言需要另行定义误操作与恢复规则。

**主动互动作为实验插件。** 默认关闭，沿用全局与每群双开关，增加安静时段、
日发送上限与对失败重试的限制。优先从明确配置的定时消息开始；环境聊天插话
需要临时观察群消息，须另行说明数据范围与同意方式，不借此开启默认群聊收集。
收到明确的限制信号或维护者停用指令时暂停主动发送，提供人工排查指引；
未知状态不声称已识别账号风控，不自动登录或尝试绕过限制。

## 6. 工程落点与实施顺序

继续保留 `plugins → services → core`，在现有边界内增量开发：

| 增量 | 主要落点 | 完成条件 |
| --- | --- | --- |
| M1 诊断与群设置 | CLI/应用生命周期、连接状态服务、storage 迁移、feature/help 插件 | 状态准确、迁移兼容、权限与帮助一致 |
| M2 网页工具 | read 插件、web 提取、独立摘要服务 | 无 AI 可用、摘要可选、安全与失败反馈通过 |
| M3 表情包 | meme 插件、本地 provider、图片校验与消息发送 | 本地检索和容器发送通过，来源说明完整 |
| M4 开源发布 | docs、模板、CI、升级与安装验证 | v0.2.0 所有必选项与干净安装/旧库升级通过 |
| M5 AI 增强 | 工具分发、可选模型能力、短期上下文 | 两项分别验收后发布 v0.2.1 |

M1 → M2 → M3 → M4 是推荐的首轮开发顺序。每个增量形成可审查的 PR，保留
可独立运行的中间状态；不先搭一个庞大的调度器或通用插件平台。
本方案中的命令和模块名是建议接口，细节在对应增量开始时确定，发布文档同步最终实现。

## 7. 发布验收与测试重点

- 保留 `/help`、`/ping`、明确 @ 规则、权限、限频、隐私与旧命名兼容的回归测试。
- 配置和旧库迁移用临时文件测试，禁止测试读取维护者的 `.env` 或真实数据卷。
- 网络使用模拟 HTTP/DNS，OneBot 使用带令牌模拟连接；不依赖真实账号或模型额度。
- 重点验证拒绝路径：越权、禁用、超时、SSRF、正文注入、超限图片和目录逃逸。
- 验证禁用的插件与能力不会出现在可用帮助或 AI 能力说明中。
- 最终通过 pytest、Ruff、wheel/sdist、Compose 配置和 Docker 构建；测试数量不是验收目标。
- 更新 `.env.example`、README、插件说明与 CHANGELOG，明确现有功能与后续计划。
- 使用备份的旧库完成升级演练；首次安装和升级演练都通过才形成发布候选版本。
