# ALING v0.4 WebUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付具有 NapCat 风格布局、ALING 蓝色主题的可选管理面板，支持状态、功能、素材和定时消息管理。

**Architecture:** WebUI 挂载于现有 FastAPI，与 QQ 指令调用同一个 Runtime 和服务层。
登录会话及诊断只存内存，运行时设置仍存原 SQLite，素材仍用受限本地清单。
采用随 Python 包发布的原生 HTML/CSS/JavaScript，不增加独立前端服务。

**Tech Stack:** Python 3.12+、现有 NoneBot2/FastAPI、SQLite、Pillow、pytest/httpx，以及浏览器原生能力。

**Spec:** [已确认的 v0.4 设计](../specs/2026-10-11-v0.4-webui-design.md)。设计方向和视觉规范已获用户认可；本实施计划供开工前评审。

## Global Constraints

- 四个首版页面：概览、群与功能、表情包、定时消息；模型与人格只读，不增加配置编辑、终端或群处罚接口。
- 品牌蓝 `#4D6BFE`、白字主按钮蓝 `#405DE6`，浅色/深色与窄屏适配；普通文字对比度至少 4.5:1。
- `WEBUI_ENABLED=false`；独立登录密钥至少 43 个 URL 安全字符，身份必须属于 `SUPERUSERS`；默认本机访问。
- 会话 8 小时、最多 8 个，超限撤销最早会话；登录失败每来源 5 次/分钟、全局 20 次/分钟。
- Login body 1 KiB；一般管理请求体 16 KiB；图片流 5,000,000 字节；鉴权与 CSRF/来源检查先于业务体解析。
- 一次性记忆确认有效 60 秒、最多 1000 条，绑定可信身份、群和来源；WebUI 还绑定登录会话。
- 普通列表每页最多 100 条；QQ 群快照最多 1000 条且标注截断；状态查询缓存 30 秒、总超时 10 秒。
- 最近诊断最多 100 条、24 小时过期；不存原始聊天、提示、API 结果、敏感请求或原始日志。
- 图片单帧、最多 12,000,000 像素；清单最多 1,000,000 字节/5000 条；描述 200 字、标签 32 个且各 80 字。
- 上传并发最多 2 个；每部署者 30 次/10 分钟，失败计数；上传文件总容量 200,000,000 字节。
- 素材移除只删除索引、保留原文件；未知清单字段与未修改条目保留；损坏清单不能被空清单替换。
- 保留 `data/ryxbot.db`、Compose 项目和所有现有卷；面板关闭兼容原部署；根文件系统继续只读、bot 继续非 root。
- 禁止读取真实密钥、修改真实账号配置或在开发期间切换运行实例；自动验证用临时目录/数据库和虚构凭据。
- 不自动登录 QQ、发送测试群消息、重启 NapCat、推送、创建 Release 或公开部署。

## Review Focus

1. 编辑中登录会话到期：保留未提交输入，提示重新登录，不自动重放上传或写操作（Task 2/3）。
2. QQ 关闭 AI 时浏览器有待确认记忆：旧确认失效，旧请求不能恢复已清空的会话（Task 1/3）。
3. 手工清单含额外字段或共享图片路径：编辑保留字段，移除条目不能删除他人引用的原图片（Task 4）。
4. 同一天从不同入口删除/重建计划：不能重置发送声明，也不进行立即发送（Task 5）。
5. HTTPS 反代与 OneBot 内部 Host 并存：管理来源检查严格，OneBot 的 `bot:8080` 接入继续可用（Task 2/6）。
