# ALING v0.5 Controlled Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver opt-in, policy-gated SearXNG search, bounded AI search/read flows, approved-source static online memes, and owner panel controls while preserving v0.4 behavior and data.

**Architecture:** Keep NoneBot handlers thin and place policy, search, source validation, task budgets, and temporary online media in runtime-owned services. All entry points use the same server-side authorization and source gates; SearXNG uses a dedicated fixed-origin client, while public pages and images continue through SSRF-safe clients. SQLite stores runtime policy, and the existing authenticated WebUI exposes owner controls and diagnostics.

**Tech Stack:** Python 3.12+, NoneBot2 / OneBot V11, httpx, SQLite, Pillow, SearXNG, Docker Compose, FastAPI, static JavaScript, pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-10-12-v0.5-controlled-search-design.md`

## Global Constraints

- New global and group `search` and `online_meme` switches default off; online meme mode defaults to `local`; approved media sources default to empty.
- Keep `web` and `meme` semantics; direct `/read <explicit URL>` keeps the v0.4 gate and SSRF behavior.
- `/search` and online memes require the existing AI feature and credentials for one conservative, history-free intent classification; `/search` does not require function calling.
- User/model text cannot choose SearXNG URL, engine, category, page, source policy, image path, or permission; unknown/unavailable classification fails closed.
- Search results, pages, and image metadata are untrusted. Validate each actual URL before showing, reading, or downloading it.
- Preserve `data/ryxbot.db`, Compose project/volume names, NapCat account configuration, OneBot paths/tokens, and local meme manifest/data.
- Do not persist ordinary chat bodies, raw queries, search results, webpage bodies, or online image history. Diagnostics contain only fixed categories, exception types, counts, and timestamps.
- All external calls have explicit timeouts and byte/result limits; no redirects, proxy inheritance, shell execution, login automation, CAPTCHA bypass, or public SearXNG fallback.
- Each task is implemented by a fresh implementation subagent and checked by a separate fresh review subagent before integration proceeds; the primary agent owns integration and whole-branch acceptance. Never let one agent review its own task.
- Use fake credentials, temporary SQLite/directories, mocked model/search/page/image/OneBot transports for automated tests. No real QQ account, remote deployment, or publishing without later explicit authorization.

## Review Focus

- A group ID, owner ID, result ID, or source ID supplied by the caller is forged or belongs to another group; prove trusted identity and task bindings reject it in Tasks 1, 2, 5, and 7.
- A permitted host is disguised by IDNA, trailing dots, encoded paths, subdomain suffixes, redirects, alternate ports, or mixed public/private DNS; prove canonical boundary matching and public-client rejection in Tasks 2 and 5.
- A request asks for a permitted-looking mixed purpose, private information, search operators, or prompt injection; prove preflight plus uncertain classifier output refuses before SearXNG in Tasks 2 and 3.
- A downstream model/search/page/image request hangs, retries, returns malformed/oversized data, or races with feature disable; prove shared budgets, bounded parsing, and revoke-before-send in Tasks 3–6.
- Existing databases, direct URL reading, local memes, old configured AI tools, and optional-profile-off deployments must continue to work; prove migration and regression paths in Tasks 1, 4, 5, 7, and 8.

## File Map

The implementation follows existing service/route/test boundaries; new units have one responsibility each.

- `src/aling/core/storage.py`: schema migration and durable global/group search policy state; preserve current schema and rows.
- `src/aling/core/config.py`: fixed internal SearXNG origin and bounded connection settings only; no API key or editable user URL.
- `src/aling/services/features.py`, `src/aling/plugins/commands.py`, `src/aling/services/help.py`: feature dependencies, owner/group command controls, user-visible help/errors.
- New `src/aling/services/search_policy.py`: immutable task scope, purpose/source policy, classifier protocol, URL/host normalization, and common authorization gate.
- `src/aling/services/search_policy.py`: trusted task-context factory that accepts identity only from a QQ event or authenticated panel session; model/tool arguments cannot construct an authorized context.
- `src/aling/services/search_policy.py`: runtime task registry for active task cancellation and policy-revision revocation.
- New `src/aling/services/search.py`: fixed-origin SearXNG client, strict response parsing, search result IDs, query/result bounds, and owner probe.
- New `src/aling/services/search_budget.py`: task deadline, operation/request counters, concurrency slots, and in-process usage quotas.
- `src/aling/services/search_budget.py`: shared `deliver_with_budget(budget, send_operation)` wrapper applies the reserved final three seconds to QQ text and image sends.
- `src/aling/services/ai.py`, `src/aling/services/tools.py`, `src/aling/plugins/ai_chat.py`, `src/aling/runtime.py`: scheduled model calls, bounded multi-round tools, task context, runtime lifecycle, and truthful capability prompt.
- New `src/aling/services/online_memes.py`, plus `src/aling/services/memes.py` and `src/aling/plugins/meme.py`: mode selection, safe downloads, opaque temporary resources, and send-time revalidation.
- `src/aling/webui/routes_features.py`, `routes_status.py`, new `routes_search.py`, `webui/__init__.py`, `static/index.html`, `static/app.js`, `static/pages/*.js`, and `static/styles.css`: owner policy controls, dependency status, bounded probe, and blue responsive UI.
- `compose.search.yaml` and `deploy/searxng/settings.yml.example`: optional isolated SearXNG service/config. No default host port.
- `.env.example`, `README.md`, `docs/architecture.md`, `docs/verification.md`, and a search operations guide: opt-in setup, source review, data flow, rollback, and diagnostics.
- `tests/test_search_policy.py`, `tests/test_search.py`, `tests/test_search_budget.py`, `tests/test_online_memes.py`, `tests/test_ai_tools.py`, existing storage/feature/plugin/WebUI tests, and `tests/webui/fixtures/`: focused deterministic proof for each service and integration boundary.

## Delivery Method

Execute tasks in order because later interfaces depend on earlier policy and task-context contracts. For each task, dispatch one implementation subagent, integrate its changes, then dispatch a different reviewer subagent with the task acceptance criteria and resulting diff. Address blockers before beginning the next task. Reviewers must inspect behavior and tests, not just formatting. After Task 8, run the whole-branch review and full acceptance suite once; do not ask agents to modify the same files concurrently.
