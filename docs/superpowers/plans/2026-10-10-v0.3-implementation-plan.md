# ALING v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the full roadmap through ALING 0.3.0: operator diagnostics, per-group feature controls, safe web and meme tools, optional AI tool calls and ephemeral sessions, permission-checked group moderation, and opt-in scheduled messages.

**Architecture:** Preserve plugins → services → core, NoneBot native plugins, passive OneBot V11, SQLite, the existing database path and Compose data volumes. Add additive schema migrations and narrow services reused by commands and optional AI tools. A single lifecycle-managed scheduler sends only explicitly configured text behind the existing proactive gate.

**Tech Stack:** Python 3.12+, NoneBot2 / OneBot V11, SQLite, httpx, BeautifulSoup, Pillow for image decoding, zoneinfo, pytest, Ruff, uv and Docker Compose.

**Spec:** docs/roadmap-v0.2.md, sections 3–8.

## Global Constraints

- Keep data/ryxbot.db, Compose project/data volume names, the ryxbot CLI and RYXBOT_ENV_FILE compatibility.
- Never read, copy, log or commit real .env, credentials, NapCat data, SQLite contents or personal meme assets.
- AI memory, AI tool calls, web and meme functions, and proactive sending default off.
- No model-selected shell commands, Python execution, arbitrary plugin imports/paths, raw CQ segments or group-management actions.
- Preserve group allow-listing, admin/superuser checks, AI limits, privacy logs, HTTP timeouts/size limits and SSRF protection.
- Never collect ordinary group chat; short memory stores only explicit mentions in bounded process memory.
- Keep /health as process liveness for Compose; do not make NapCat startup depend on QQ connection readiness.
- Scheduled messages have bounded execution, a daily limit and no automatic retries; missed windows are skipped.
- Set package and user-visible version to 0.3.0; do not create a remote tag, release, image or deployment.

## Review Focus

- Legacy database without schema_version: migration preserves the old switch and repeated startup is safe.
- Missing, duplicate, malformed or privileged moderation target: reject before OneBot mutation.
- Bot connected while QQ status is false, unknown, unavailable or reconnecting: report accurately and never infer risk-control cause.
- Restart, timezone/DST change, schedule edit/disable during a due tick: no duplicate or stale catch-up message.
- Malicious web text, symlinked/oversized/corrupt images, unsupported model tools and session eviction: bounded failure with no privacy leak or cross-group access.
