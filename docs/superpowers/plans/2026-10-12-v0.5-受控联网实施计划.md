# ALING v0.5 受控联网实施计划

> **供代理式开发者使用：** 实施本计划时必须使用 `superpowers:subagent-driven-development` 子技能，按任务逐项执行。步骤使用复选框（`- [ ]`）跟踪。

**目标：** 交付默认需显式开启、受策略控制的 SearXNG 搜索、受限的 AI 搜索与网页读取流程、仅从获准来源获取的静态在线表情包，以及面板管理员控制，同时保留 v0.4 行为和现有数据。

**架构：** 保持 NoneBot 处理器精简，将策略、搜索、来源验证、任务预算和临时在线媒体放在由 Runtime 管理的服务中。所有入口共用服务端授权与来源校验；SearXNG 使用固定目标地址的专用客户端，公开网页和图片仍走具备 SSRF 防护的客户端。SQLite 保存运行时策略，现有已鉴权 WebUI 提供管理员控制和诊断。

**技术栈：** Python 3.12+、NoneBot2 / OneBot V11、httpx、SQLite、Pillow、SearXNG、Docker Compose、FastAPI、静态 JavaScript、pytest、Ruff。

**设计文档：** `docs/superpowers/specs/2026-10-12-v0.5-controlled-search-design.md`

## 全局约束

- 新增的全局及群级 `search`、`online_meme` 开关默认关闭；在线表情包模式默认为 `local`；获准媒体来源初始为空。
- 保持 `web` 和 `meme` 现有语义；直接读取 `/read <明确 URL>` 继续沿用 v0.4 权限门和 SSRF 行为。
- `/search` 和在线表情包需要现有 AI 功能已启用并配置凭据，以进行一次保守且不读取历史的意图分类；`/search` 不要求模型支持函数调用。
- 用户或模型提供的文本不能指定 SearXNG 地址、引擎、类别、页面、来源策略、图片路径或权限；分类结果未知或分类服务不可用时必须拒绝操作。
- 搜索结果、网页和图片元数据均视为不可信；展示、读取或下载前逐个验证实际 URL。
- 保留 `data/ryxbot.db`、Compose 项目名和数据卷名、NapCat 账号配置、OneBot 路径和令牌，以及本地表情包清单与数据。
- 不持久化普通聊天正文、原始查询、搜索结果、网页正文或在线图片历史。诊断只记录固定类别、异常类型、计数和时间戳。
- 所有外部调用均设置明确超时和字节数/结果数量上限；禁止跟随重定向、继承代理设置、执行 Shell 命令、自动登录、绕过 CAPTCHA 或回退到公共 SearXNG 实例。
- 每项任务均由新的实现子代理完成，并由另一个独立的新审查子代理检查后，才可进入集成。主代理负责集成和全分支验收。不得让代理审查自己实现的任务。
- 自动化测试使用假凭据、临时 SQLite/目录，并模拟模型、搜索、网页、图片和 OneBot 传输。未经之后的明确授权，不接入真实 QQ 账号、不远程部署、不发布。

## 审查重点

- 调用者伪造群号、所有者 ID、结果 ID 或来源 ID，或使用属于其他群的标识；在任务 1、2、5、7 中证明可信身份和任务绑定能够拒绝此类输入。
- 允许的主机通过 IDNA、尾随点、编码路径、子域名后缀、重定向、替代端口或混合公私 DNS 响应伪装；在任务 2、5 中证明规范化后的边界匹配和公开客户端拒绝逻辑有效。
- 请求包含表面上允许但实际混杂的用途、隐私信息、搜索运算符或提示注入；在任务 2、3 中证明预检和不确定分类会在请求 SearXNG 前拒绝。
- 下游模型、搜索、网页或图片请求挂起、重试、返回畸形/超大数据，或与功能关闭并发；在任务 3–6 中证明共享预算、有界解析和发送前撤销有效。
- 现有数据库、直接 URL 读取、本地表情包、旧版已配置 AI 工具以及关闭可选 profile 的部署必须继续工作；在任务 1、4、5、7、8 中证明迁移和回归路径。

## 文件范围

实现沿用现有服务、路由和测试边界；新增单元各自承担一项职责。

- `src/aling/core/storage.py`：数据库结构迁移和持久化的全局/群级搜索策略；保留现有结构和行数据。
- `src/aling/core/config.py`：仅配置固定的内部 SearXNG 地址和有界连接参数；不配置 API Key 或可由用户编辑的 URL。
- `src/aling/services/features.py`、`src/aling/plugins/commands.py`、`src/aling/services/help.py`：功能依赖、所有者/群命令控制、用户可见帮助和错误文案。
- 新增 `src/aling/services/search_policy.py`：不可变任务范围、用途/来源策略、分类器协议、URL/主机规范化和通用授权门。
- `src/aling/services/search_policy.py`：可信任务上下文工厂；身份只能来自 QQ 事件或已鉴权面板会话，模型/工具参数不能构造已授权上下文。

- 新增 `src/aling/services/search.py`：固定目标地址的 SearXNG 客户端、严格响应解析、搜索结果 ID、查询/结果上限和所有者探测。
- 新增 `src/aling/services/search_budget.py`：任务截止时间、操作/请求计数、并发槽位和进程内用量配额。
- `src/aling/services/search_budget.py`：共用的 `deliver_with_budget(budget, send_operation)` 包装器，将预留的最后 3 秒用于 QQ 文本和图片发送。
- `src/aling/services/ai.py`、`src/aling/services/tools.py`、`src/aling/plugins/ai_chat.py`、`src/aling/runtime.py`：调度模型请求、有界多轮工具、任务上下文、Runtime 生命周期和如实说明能力的提示词。
- 新增 `src/aling/services/online_memes.py`，以及 `src/aling/services/memes.py`、`src/aling/plugins/meme.py`：模式选择、安全下载、不透明临时资源和发送时复核。

- `.env.example`、`README.md`、`docs/architecture.md`、`docs/verification.md` 和搜索运维指南：选择性启用、来源审查、数据流、回滚和诊断。
- `tests/test_search_policy.py`、`tests/test_search.py`、`tests/test_search_budget.py`、`tests/test_online_memes.py`、`tests/test_ai_tools.py`、现有存储/功能/插件/WebUI 测试及 `tests/webui/fixtures/`：为每项服务和集成边界提供聚焦且确定的验证。

## 交付方式

按顺序执行任务，因为后续接口依赖前面确立的策略和任务上下文契约。每项任务先派发一名实现子代理，集成其变更后，再派发另一名审查子代理，根据任务验收标准和最终差异进行检查。解决阻塞问题后再开始下一项任务。审查必须检查行为和测试，不能只看格式。任务 8 完成后，再执行一次全分支审查和完整验收套件；不要让多个代理同时修改相同文件。

### 任务 3：任务预算、SearXNG 客户端、`/search` 和可选 Compose 服务

**接口：**

- `TaskBudget.start(now, limits)`、`reserve_model_request()`、`reserve_external_operation(kind)`、`remaining_work_seconds(now)` 和 `can_send(now)` 实现统一的 60 秒任务生命周期；外部工作必须在第 57 秒前结束。
- `SearxngClient.search(query, *, category, language, safe_search, limit, budget) -> list[SearchHit]` 只向配置的固定内部地址上的 `/search` 发送表单编码 POST 请求；只接受服务端生成的参数。SearXNG 官方 API 支持表单 POST；启用 JSON 输出后可返回 JSON：[Search API](https://docs.searxng.org/dev/search_api.html)。
- `SearchService.search(context, text, classifier, budget) -> AuthorizedSearchResults` 调用任务 2 的唯一授权门，再调用 SearXNG 客户端，并重新验证所有返回 URL。
- `/search <关键词>` 最多返回三个获准的标题/摘要/来源链接及稳定的安全错误码；要求现有 `ai`，不要求 AI 函数调用或 `web`。

- [ ] **步骤 1：先编写预算和客户端测试。** 断言以下上限：任务总时长 60 秒，57 秒后停止外部工作；工具选择最多 3 轮；实际模型 HTTP 请求最多 5 次（含重试）；外部操作累计最多 4 次（含重试）；每任务最多搜索 1 次；最多 3 条结果；子请求最多 10 秒且不得超过剩余时间；实例并发 2、单群并发 1；每人冷却 15 秒、每小时最多 10 次（按用户跨群计数）、每群每小时最多 30 次、每实例每小时最多 100 次。模拟 JSON 成功、未开启 JSON 时的 403、畸形/超大响应、超时、重定向尝试、查询参数注入和上游错误。
- [ ] **步骤 2：运行聚焦测试，确认新预算/客户端 API 尚不存在。** 运行：`uv run pytest tests/test_search_budget.py tests/test_search.py -q`。预期：导入或行为测试失败。
- [ ] **步骤 3：实现单调计时的任务预算和逻辑任务准入。** 旧 AI 冷却/每小时配额按一个逻辑任务计费一次；每次实际模型 HTTP 请求尝试都消耗任务请求计数并占用共享模型并发槽位。模型和网络信号量分开，避免嵌套获取同一槽位导致死锁。

只有在所有自动化测试都使用模拟服务且全部通过，Ruff、格式、锁文件、构建和 Compose 检查通过，关闭可选 profile 时仍保持兼容，面板明确展示来源策略和模型数据流，并且独立全分支审查无未解决阻塞项时，v0.5 分支才可交由用户验收。中文实时搜索质量、上游引擎实际行为、获准图片来源可用性及 QQ 发送/重启行为仍是由所有者控制的实地验收步骤。通过本地 Docker 检查本身不构成部署授权。
