# 阿零（ALING）架构

阿零由 Jack233_ 在 onlyryx 品牌下维护，是以实用工具为核心、AI 群友聊天为补充的开源 QQ 群机器人。
Python 3.12+、NoneBot2、OneBot V11、NapCatQQ、SQLite 与插件化服务分层构成主干。

## 边界与数据流

NapCatQQ → OneBot V11 反向 WebSocket → NoneBot matcher → service → OneBot 回复。
`app.py` 管理驱动、插件及生命周期；`plugins/` 只处理事件与消息展示；`services/`
封装模型、网页、表情包、群管理、短期会话与主动消息；`core/` 提供配置、权限、限频、
SQLite、扩展协议和日志。扩展使用 NoneBot 原生插件，不引入自制插件框架。

普通 `/help`、`/ping`、`/status` 与群内 `/read`、`/search`、`/meme` 由显式指令调用。
AI 只响应群内明确 @ 机器人并包含文字的消息，不把昵称或回复自动附带的 @ 当作明确提及。
模型输出作为纯文本；图片由本地表情包服务验证后构造成图片段。群管理只接受独立的
`/mute`、`/unmute` 指令，AI 工具白名单中不包含任何管理操作。

## 功能开关、记忆与模型工具

AI/web/meme/memory 全局开关默认关闭；配置的超级用户可通过 `/feature global` 调整运行时全局开关，
全局值和群级设置均存在 SQLite 中。旧环境功能许可不再阻挡开关；开启 AI/记忆仍需模型凭据，
记忆还依赖全局及本群 AI。新群功能默认关闭，必须显式启用；短期记忆还要求群管理员确认。
关闭全局 AI 会同时禁止使用短期记忆。主动发言保留全局 `PROACTIVE_ENABLED` 与本群
`/proactive on` 双开关。`/help` 根据已加载插件元数据和当前群设置过滤命令。

短期会话按 `(group_id, user_id)` 隔离，只记明确 @ 交互，保存在进程内并受 TTL、轮数、
字符数和会话总数限制。过期数据不再用于请求，并由生命周期管理的任务在一分钟内清理。
关闭某群 AI/记忆会清空该群缓存；关闭全局 AI/记忆或重启清空全部会话；`/forget`
在功能关闭时仍可清除当前用户的会话。清除操作使先前已开始的问答失去写入资格。
默认关闭时，模型仅收到当前提问。

AI 工具调用默认关闭，由面板中超级用户的 SQLite 设置控制；`AI_TOOLS_ENABLED` 只在初次初始化时提供种子值。
仅向兼容工具调用的模型公开当前群可用的 `web_search`、`web_read`、`meme_search` 工具；搜索任务的后续读取
必须引用本任务获准来源。每次模型请求共用并发调度与任务预算，最多三轮工具选择、五次模型请求和四次外部操作。
模型响应结构在调用工具前验证；每个工具调用都有结果响应，参数进入统一 service 后再次检查开关、
策略版本、来源、白名单与输入边界。网页内容、搜索结果与图片元信息是不可信资料。显式联网调用失败时
不会伪装成已经联网的普通聊天。

受控搜索依赖可选 SearXNG profile；应用端只请求固定内部 origin 的 `/search`，发送有界 POST 参数，
禁用环境代理和重定向并限制 JSON 大小。部署者和群级策略取交集：用途、来源、功能开关和限额都须允许；
AI 用途分类使用无历史、无工具的单独模型请求，不是确定性安全证明。获准结果逐条验证来源与 URL；
网页读取及在线图片下载继续使用各自的公网 DNS、固定 IP、无重定向和大小检查。在线表情临时数据只在进程内，
策略收紧、过期或重启即撤销。详细部署数据流见 [联网运维说明](search-operations.md)。

## 持久化和外部操作

- SQLite 保存运行时全局/群级 AI/web/meme/memory/search/online_meme 与主动开关、部署者确认、来源/用途策略、
  AI 工具偏好、管理员配置的定时文本和独立的最后尝试日期；
  不保存群聊正文、AI 会话、网页内容或表情包搜索记录。版本化迁移使用事务并保持旧表与数据卷。
- `/read` 只访问公网 HTTP(S) 标准端口，拒绝凭据、非公网或混合 DNS、重定向、代理、压缩内容，
  并将请求固定到已校验 IP。响应、网页正文、URL 与异常请求体不写日志。
- `/meme` 从部署者维护的本地清单按标签检索。资源编号不暴露路径；解析后的文件必须位于素材根目录，
  图片解码时检查格式、大小、像素与动画帧数。
- `/mute` 与 `/unmute` 从真实群消息事件读取操作者角色，并向 OneBot 核实机器人和目标角色；
  要求两者均满足 QQ 权限条件。群允许列表和每用户限频继续生效。
- 定时消息仅在配置时间五分钟窗口内运行；使用 `PROACTIVE_TIMEZONE`、安静时段和每日/每小时上限。
  原子记录计划所属日期和实际尝试日期，五分钟窗口可跨午夜；删除重建配置或重启不会重置声明。
  已尝试的同一次计划不会重复执行，同一实际日期也不会再发送；发送失败或错过窗口不会自动重试。
  断连时跳过，不自动登录或探测风控。
- `/health` 仅报告应用存活。`/status` 仅允许配置的超级用户显式请求 OneBot 状态，不推断手机端风险或封禁。

## 日志与安全

OneBot 访问令牌必须设置；默认本机监听、反向 WebSocket 模式，不主动登录任何 QQ 账号。
日志过滤框架消息正文、URL、token、异常详情和局部变量，仅保留固定事件类别及异常类型。
外部 HTTP、模型、调度发送和 OneBot API 均有超时。部署者提供的模型地址是可信配置，群员和模型不能修改。

## 扩展协议与交付

`MemeProvider` 使用不透明资源编号；`WebParser` 提供受限网页解析；`GroupAction` 必须接收由可信事件
构造的权限上下文。插件开发示例与测试约定见 `docs/plugins/example_plugin.py`。

测试使用临时数据库、mock HTTP/DNS、fake OneBot；不会读取维护者 `.env` 或账号数据。
插件设置、群功能门、权限、限频和离线验证示例见 `docs/plugins/README.md`。
NapCat 为 Compose 的显式 `qq` profile，默认 Compose 只运行 bot。升级、手工接入和操作说明见根目录 README。

兼容数据标识继续保留：SQLite 默认路径 `data/ryxbot.db`、Compose 项目名 `ryxbot`、
`bot-data` / `napcat-qq` / `napcat-config` 卷名，以及 `ryxbot` CLI 和 `RYXBOT_ENV_FILE`。
