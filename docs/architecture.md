# ryxbot 第一阶段架构

onlyryx 旗下独立开源 QQ 群机器人。功能插件为主，AI 聊天为辅。

## 边界与数据流

NapCatQQ → OneBot V11 反向 WebSocket → NoneBot matcher → 服务 → 回复。
`app.py` 负责初始化驱动、适配器、插件和服务生命周期；`plugins/` 只处理 QQ
事件与消息展示；`services/` 处理模型访问、受控网页读取和主动消息发送；
`core/` 提供配置、权限、限频、SQLite 群设置、扩展协议与日志。
依赖通过一个运行时容器共享，不引入自制插件框架；使用 NoneBot 原生插件加载。

基础指令优先于 AI：`/help`、`/ping`、群管理员用 `/proactive on|off`。
AI 仅接收群内明确 @ 本机器人且包含文本的提问，排除命令、自身消息与私聊。
昵称或回复消息本身（包括紧随 reply 的自动附带 @）不能触发 AI；另加独立 @ 可触发。
模型只得到人格提示和当前提问；没有历史、
QQ 账号标识、工具执行器或系统命令入口。模型输出以纯文本消息段发送。

## 状态与安全

- SQLite 只保存每群主动发言开关，默认 false；不记录聊天或模型输出。
- 主动消息全局开关默认 false；未来插件须经统一发送服务检查全局和群开关、
  群允许列表、冷却与小时频率。第一阶段没有主动发言调度器。
- AI 提问按群限频且全局限制并发；输入、输出、响应大小与请求总时长有上限。
  HTTP 服务请求 identity 编码，读取流前拒绝压缩响应，避免解压越过内存限制。
- OneBot 必须配置访问令牌；默认只监听本机，不主动连接任何账号。
- 应用日志只记录固定事件与错误类别，不记录消息、URL、密钥或请求/响应体。
- 网页访问只允许 HTTP(S) 标准端口，拒绝用户信息、非公网地址和重定向；
  全部 DNS 结果须为公网，实际连接使用检查后的固定 IP，TLS 保留原始主机名。
  禁止环境代理；限制响应大小与总时长。模型服务地址由部署者可信配置，
  允许显式配置本地 OpenAI 兼容服务，不能从群消息修改。
- 群管理单独验证真实事件角色或配置的超级用户；操作范围服从群允许列表。
  AI 不调用管理接口。未来封禁等操作还须验证机器人自身的 QQ 权限。

## 扩展接口

`MemeProvider.search()` 返回结构化表情包结果；`WebParser.parse()` 返回结构化网页
摘要；`GroupAction` 接受可信事件构建的权限上下文。第一阶段没有搜索供应商、
群封禁功能或模型工具调度。后续插件可以调用统一 SafeWebClient 与权限函数。

## 交付检查

离线测试覆盖指令、明确 @ 条件、模型成功/超时/错误、限频、权限、SQLite 设置、
SSRF 与日志隐私；FastAPI TestClient 模拟带令牌的 OneBot 连接与 API 往返。
检查安装、lint、wheel/sdist 构建和未配置凭据时的启动失败行为。
Docker Compose 默认只有 bot；NapCat 为显式启用的 profile，账号登录由用户完成。
